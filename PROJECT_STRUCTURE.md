# Структура исходников

Проект организован по функциям приложения. Все папки внутри `quadrofriends/` входят в один Xcode target и отображаются в Xcode благодаря синхронизированной группе файлов.

```text
quadrofriends/
├── App/                 # Точка входа и вкладки
├── Core/
│   ├── Models/          # Модели, используемые несколькими экранами
│   ├── Components/      # Общие элементы интерфейса
│   ├── Networking/      # API-клиент, сессия, WebSocket (см. API_SETUP.md)
│   ├── Theme/           # Тема и фон
│   └── MockData.swift   # Демонстрационные данные
├── Features/
│   ├── Auth/            # Первый экран и VK ID
│   ├── Chats/           # Список и экран чата (UIKit), API/ — ручки и репозиторий чатов
│   ├── Map/             # Карта, поиск на карте, настройки
│   ├── Profile/         # Профили и редактирование
│   └── Routes/          # Список, детали, метки и отправка маршрутов
└── Assets.xcassets/
```

Новый экран размещайте в папке соответствующей функции. Вспомогательные типы, нужные одному экрану, держите в том же файле с модификатором `private`. Общую модель или компонент переносите в `Core`, когда он используется в нескольких функциях.

Вкладка «Чаты» написана на UIKit: `ChatsTab` встраивает `UINavigationController` в SwiftUI `TabView`, список чатов и переписка построены на `UICollectionView` с compositional layout и diffable data source, вёрстка — кодом через Auto Layout. Вспомогательные окна (новое сообщение, согласие на геопозицию, карта геопозиций, профиль участника) остаются на SwiftUI и открываются через `UIHostingController`.

Отдельный Swift Package полезен, когда появляется самостоятельный модуль с чётким API, который нужно переиспользовать или выпускать независимо. Сейчас папки внутри одного target дают простую навигацию без лишних границ между модулями.
